# Social Trace

**通过对话追踪博主动态、查询言论、总结观点、管理监控任务。**

Social Trace 是运行在 DeepSeek Harness 上的**博主言论追踪与分析 Agent**，以插件形式安装。它持续追踪你关注的微博、雪球博主，将动态保存在本地，形成可查询、有来源的言论记录。你可以通过对话检索历史言论、总结观点、创建定时总结任务，也可以添加博主、调整频率、启停监控与历史缓存；配置变更先预览，确认后执行。新动态通知可通过 dsh-im 推送。

## 为什么用它

- **平台上的内容会消失。** 博主删帖、改口、设置半年可见，刷过去就找不到了。Social Trace 把看到的动态按博主留在本地，之后还能搜索、导出。
- **不想每天手动刷主页。** 按博主设置检查频率和时间段，只在新动态出现时记录和提醒。
- **不想把账号交给 AI。** 登录在插件自己的浏览器里完成，Cookie 不经过模型，资料库只落在本机。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 对话与任务 | 复用 DSH 默认模型，查询、总结、添加监控、调整频率和管理本地总结任务；变更确认后执行 |
| 按博主监控 | 微博、雪球；每位博主独立开关、频率和时间段 |
| 增量检查 | 定时读取新动态；关机/重启后补查期间仍可见的内容 |
| 历史缓存 | 按日期范围回补旧动态，支持断点续传，不重复抓取 |
| 完整留档 | 正文、转发原文、配图；按平台和博主 UID 分目录保存 |
| 本地资料库 | SQLite + 按博主分目录的 Markdown；支持中文正文搜索 |
| 导出 | 单博主 Markdown / JSONL，正文和来源一起带走 |
| 可视化流向 | 博主 → 平台 → Social Trace → 资料库四层拓扑，状态、进度、异常一眼可见 |
| dsh-im 推送 | 新动态原文推送到 QQ / 微信；支持多个接收目标；默认关闭 |
| 本地优先 | 授权会话只存插件目录（0600），资料库不额外上传云端，不写进仓库 |

## 它怎么工作

1. **添加博主**：粘贴微博/雪球主页链接或数字 UID。
2. **选择记录方式**：从现在开始，或按日期范围缓存历史消息。
3. **交给它跑**：按设定频率检查；新内容入库后写 Markdown、下载配图；需要时通过 dsh-im 推送。
4. **通过对话使用**：查询已保存的言论、总结观点，或提出监控与任务调整要求。

## 安装

需要 DeepSeek Harness 桌面版、Google Chrome，以及 Node.js 22.19 或以上。

在 DeepSeek Harness 的「设置 → 插件」中安装 `dsh-social-trace@latest`。

desktop profile 由 Harness 应用管理，CLI 的 `dsh plugin --profile desktop add ...` 会被拒绝；不要用这条命令安装 desktop 插件。开发调试时，请使用独立的非 desktop profile，或通过 Harness 插件管理器安装本地构建。

安装后完全退出并重新打开 Harness，在侧栏打开 Social Trace。

## 快速开始

1. **选保存位置**：在「连接与设置」里选择资料库文件夹。
2. **登录平台**：点「登录微博」/「登录雪球」，在独立浏览器窗口完成登录，回来点「我已登录，继续」。
3. **添加博主**：粘贴主页或 UID，读取昵称/头像/总数，选择从现在记录或缓存历史。
4. **调频率**：点大屏里的博主、平台或总控齿轮，设置检查频率、时间段和历史范围。
5. **开推送（可选）**：先在 dsh-im 里连接机器人并创建接收目标，再到 Social Trace 的 dsh-im 节点添加渠道、选择博主范围、开启自动推送。

## 通过 dsh-im 推送

推送的是**新动态原文通知**，不是 AI 摘要：包含博主、发布时间、正文节选、转发引用和原文链接。

- 默认关闭；安装、打开设置或选择目标都不会自动发送。
- 只推送开启之后新采集的内容；历史缓存和此前已存内容不补发。
- 支持多个接收目标（QQ、微信等），每个目标可单独开关；一个渠道失败不影响其他渠道。
- 投递记录可查；失败或结果未知不会自动重发，避免重复打扰。
- 机器人密钥由 dsh-im 管理，Social Trace 不重复保存。

配置入口：大屏的 dsh-im 节点，或「连接与设置」里的消息推送区域。

## 与 Agent 对话

点击侧栏「新建对话」，可以查询本地资料、总结观点、创建定时总结任务，或添加监控、调整频率、启停新动态监控与历史缓存。

- 模型复用 DSH 的默认模型，插件不保存 API Key。
- 写操作只生成预览，必须在界面确认后才会执行。
- 聊天记录、总结和引用来源保存在本机资料库。
- 使用远程模型时，问答涉及到的博文文字会作为上下文发送给该模型；不需要时请缩小提问范围，或改用本地模型。

## 数据放在哪

默认在 `~/.local/share/dsh-social-trace/`，也可以在设置里改到自己的文件夹。

```text
你选择的文件夹/
  archive.sqlite       正文、任务、状态和消息
  documents/
    weibo/<UID>/       该博主的 Markdown 与配图
    xueqiu/<UID>/
```

登录会话单独保存在插件目录，权限 0600，不进入仓库，也不会复制到资料文件夹。资料库不是加密数据库；需要更高保护时请把文件夹放在加密磁盘里。

## 边界

- 需要电脑唤醒且 Harness/插件在运行；关机期间不会采集，重开后补查仍可见的内容。
- 已删除、被权限挡住或超出平台可见范围的内容无法补回。
- 平台要求登录/验证时会暂停采集，处理后继续；不会绕过验证码、轮换账号或使用代理池。
- 雪球文章只保存标题和原文链接，不保存文章正文。
- Chat 可生成带来源的本地总结、创建定时总结任务并控制监控；使用远程模型时，选定文字会交给该模型。当前总结任务按天生成本地报告，自动 IM 总结推送与 IM 内问答尚未接入。
